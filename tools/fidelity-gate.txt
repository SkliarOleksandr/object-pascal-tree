# The fidelity gate's expectations (tools\fidelity-gate.ps1): every outcome
# other than OK that is known and explained today. A unit no line names must
# be OK. Keep the reason with every line - an unexplained exception is the
# thing the gate exists to refuse. Finding ids are those of
# docs/tree-contract.md and docs/parser-fidelity.md.
#
# <corpus> <stages> <unit or file> <outcomes> <why>
#   corpus    self | studio (an extra corpus lists its own, in its file)
#   stages    * or a comma list of t0f t1 t2 t3 t3x; or, for the tree stage
#             (the file relative to the tree it was read from - the Studio
#             source root, the repository's source\ ...), parse (the file
#             parses with diagnostics) or t3r (its print does not parse back)
#   outcomes  a | list of OK DIFF XFORM-FAIL BASE-FAIL NONDET TOOL-FAIL, or
#             FAIL for parse and t3r

# The units dcc does not compile standalone - never judged.
studio * System.pas BASE-FAIL reserved unit name (E2272): only the RTL's own build compiles it
studio * SysInit.pas BASE-FAIL reserved unit name (E2272)
studio * System.Generics.Collections.pas BASE-FAIL a unit cycle through System.Rtti: F2613 standalone
studio * FMX.ZOrder.pas BASE-FAIL a unit cycle with FMX.ZOrder.Win: F2613 standalone
studio * FMX.ZOrder.Win.pas BASE-FAIL a generic cycle with FMX.Presentation.Win: F2051 standalone

# dcc itself. A NONDET outcome needs no line - the gate shows it and never
# fails on it (Vcl.Skia under -$O-, and once System.Variants under t0f). A
# variation rare enough to slip past the harness's recompiles reads as DIFF:
studio t1,t2,t3x Vcl.ControlList.pas OK|DIFF|NONDET one byte of a method-resolution entry differs in about 1 of 10 compiles of the original alone
